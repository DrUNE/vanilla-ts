# vanilla-ts

*English version: [README.md](README.md).*

Демонстрационный проект: современный компонентный UI можно собрать на **чистом TypeScript и Vite, без UI-фреймворка**. Здесь используется JSX, но не React: собственный JSX-рантайм на ~50 строк превращает каждое JSX-выражение сразу в настоящий DOM-узел. Нет виртуального DOM, нет сравнения деревьев и повторных рендеров. Страница повторяет стартовый шаблон Vite, собранный из небольших компонентов, и служит примером того, как далеко можно зайти без фреймворка.

## Ключевые идеи

- **JSX, который возвращает DOM.** `<button>Hi</button>` вычисляется в `HTMLButtonElement`. Компоненты — обычные функции `(props) => Node`.
- **Императивное состояние.** Компонент хранит локальные переменные и сам обновляет DOM в обработчиках событий (см. [Counter](src/components/Counter/index.tsx)).
- **CSS-модули рядом с компонентом.** Каждый компонент лежит в `src/components/<Name>/`: `index.tsx` и `<Name>.module.css`.
- **Алиасы путей.** `@components/*`, `@lib/*` и `@assets/*` вместо относительных `../../`.
- **Отладка без фреймворка.** В dev-режиме у элементов есть `data-source` (файл:строка), а у корней компонентов — `data-component`, так что от любого DOM-узла можно перейти к исходнику. См. [docs/debugging.ru.md](docs/debugging.ru.md).
- **Тесты.** Vitest с jsdom, на том же рантайме.

```tsx
export function Counter() {
  let count = 0

  const render = () => {
    button.textContent = `Count is ${count}`
  }

  const increment = () => {
    count += 1
    render()
  }

  const button = (
    <button type="button" onClick={increment} />
  ) as HTMLButtonElement

  render()
  return button
}
```

### Паттерн: состояние, `render` и обработчики

Компоненты без фреймворка следуют одному небольшому соглашению, показанному выше:

- **Состояние** — обычная локальная переменная (`count`).
- **`render`** — единственная функция, которая записывает состояние в DOM. Она же вызывается один раз при создании, поэтому начальная разметка строится тем же кодом, что и каждое обновление, и не дублируется в JSX.
- **Обработчики** (`increment`) меняют состояние и затем вызывают `render`.

Чем это лучше, чем весь код внутри инлайнового `onClick`:

- **Одно место для обновлений DOM.** Чтобы изменить отображение, правится ровно одна функция, а начальный и обновлённый вид не могут разойтись.
- **Обработчики описывают поведение.** Они читаются как реализуемая логика, их легко использовать для нескольких событий, а тестировать можно вызовом обработчика и проверкой DOM.
- **Отсутствие реактивности видно явно.** Раз ничего не перерисовывается само, правило «любое изменение состояния заканчивается вызовом `render()`» видно в коде и легко проверяется на ревью.
- **Легко расширять.** Второе состояние или второе событие — это новый обработчик, вызывающий тот же `render`, а не ещё одна копия кода правки DOM.

`render` обращается к `button`, объявленному ниже. Это безопасно: `render` выполняется только после создания кнопки, первый вызов стоит сразу после объявления.

## Быстрый старт

```bash
npm install
npm run dev        # dev-сервер с HMR
npm run build      # проверка типов (tsc) и сборка в dist/
npm run preview    # запуск продакшен-сборки
npm test           # один прогон тестов (npm run test:watch — режим наблюдения)
```

## Структура проекта

```
index.html                 содержит точку монтирования #app
src/main.ts                вход: глобальный CSS + mountApp()
src/components/<Name>/     index.tsx + <Name>.module.css
src/lib/jsx/               собственный JSX-рантайм (jsx-runtime.ts, jsx-dev-runtime.ts)
src/lib/SvgIcon.tsx        помощник <svg><use/></svg> для public/icons.svg
docs/                      документация для разработчиков
```

Источник JSX — выдуманный модуль `jsx-dom`, привязанный к `src/lib/jsx` и в `tsconfig.json` (`paths`), и в `vite.config.ts` (`resolve.alias`). Алиасы `@…` объявлены в тех же двух местах; держите их согласованными.

## Ограничения

Это демонстрация, а не фреймворк. Реактивности нет: ничего не перерисовывается при изменении переменной, любое обновление — ручная правка DOM.

Показанный выше `Counter` работает несмотря на это лишь потому, что обработчик клика напрямую меняет DOM (`button.textContent = ...`). Сама переменная `count` не реактивна: `{count}` в JSX считывается один раз, при создании компонента. Если бы обработчик только делал `count += 1` и не трогал DOM, текст кнопки никогда бы не изменился. Для небольших виджетов и статичных страниц этого достаточно, и именно этот компромисс проект и показывает.

## Когда расширять, а когда переходить на фреймворк

Подход можно немного расширить, прежде чем он перестанет окупаться:

- **Менеджер состояния** для состояния, общего для нескольких компонентов. Например, `zustand/vanilla` работает без React: даёт `getState`, `setState` и `subscribe`. `subscribe` всё равно нужно самим связывать с функцией `render`, так что это добавляет хранилище, а не реактивный DOM. Оговорки: хранилище — синглтон уровня модуля, а хука размонтирования для отписки нет.
- **CSS-in-JS** вместо CSS-модулей, если нужны стили, зависящие от пропсов. Могут подойти библиотеки без зависимости от React (или небольшой собственный помощник), но это ещё одна вещь, которую придётся поддерживать рядом с рантаймом.

За этой границей (общее состояние, меняющиеся списки, условный рендеринг, очистка при удалении, асинхронные данные) вы начнёте воспроизводить то, что фреймворк уже умеет, и лучше взять готовый:

- **React**: самая большая экосистема и инструменты, ценой виртуального DOM и повторных рендеров.
- **Solid**: ближе всего по духу к этому проекту. JSX компилируется в реальные операции над DOM, а тонкие сигналы обновляют только изменившееся.
- **Svelte**: компилятор, который генерирует обновления DOM из шаблонов, реактивность встроена в язык.

Переход несложен: компоненты здесь уже небольшие функции с CSS-модулями и тестами рядом, большая часть структуры сохранится.
